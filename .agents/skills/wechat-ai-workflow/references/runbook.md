# 公众号执行与交接

## 开始或接续

1. 确认本次要做的稿件、时间范围、交付路线和授权。选题未定就停在三张选题卡，已有明确选题就进入核查。用户只要求优化现稿时从该稿继续。若已有微信草稿且用户手工编辑过，先让本地正文对齐用户认可的版本，再继续修改。当前版本无法取得时标明这一点。
2. 每篇用一个稿件目录。新稿记录北京时间日期和主题短名，有雷达选题时记 ID。目录可放在仓库的 `exports/`，可公开复用的脱敏样例放在 `examples/`。Agent 换机时需要可访问该目录或完整稿包。
3. 写 `run.md` 记用户已批准的题目与范围、当前正文相对路径及 SHA-256、已完成步骤和证据、下一步、阻塞项。用了 WeWrite 就再记 `WEWRITE_HOME` 和任务 ID。依次读 `run.md`、`article.md`、核查与交付证据，从第一项尚未完成的步骤继续。正文变化时更新版本，并重做受影响的审稿和交接包。旧预览和回执只能证明旧版本。
4. 分工时协调者负责维护 `run.md`、版本合并和平台交接。采集和搜图可并行，写作和审稿在同一稿件上依次进行。同一时刻只有一个 Agent 修改正式 `article.md`，账号写入也由一人负责。每位接手人读本入口、自己的参考和上一步产物，不依赖聊天内容。
5. 本地依赖见 [安装说明](../../../../README.md#安装和首跑) 和 [WeWrite 设置](../../../../WEWRITE.md#直接使用)。只装本次路线所需依赖。同一 WeWrite 状态目录的 `current_run` 是共享指针。并行任务显式执行 `wewrite run show <任务-ID>`、`wewrite sources list --run-id <任务-ID> --json`、`wewrite run step <步骤> <状态> --run-id <任务-ID>`。无法指定任务 ID 的调用串行处理，或各自用独立的状态目录。

## 各环节操作

| 负责环节 | 开始时读什么 | 做完留下什么 |
| --- | --- | --- |
| 采集与核查 | 用户时间窗、雷达信源、已知文章或上一期记录。可先跑 `python -X utf8 radar.py run --days 3` 缩小范围，再按北京时间三个自然日核对事件时间。 | 当前时间窗的候选、事实卡和原始链接。用户选定时记录批准范围。已有雷达 ID 时用 `radar.py card <ID>` 核查，批准后可用 `radar.py export <ID> --out <目录>` 取结构化证据。 |
| 初稿 | 已批准选题、事实卡、[编辑准则](editorial.md) 和 [写作模块](../../wewrite-write/SKILL.md)。按需运行 `wewrite run start --topic <选题> --mode draft --visual-mode none` 并记任务 ID。 | 读者问题、首屏、主线、初稿及 `evidence.md`。关键证据记录支持哪条话、发布时间、时区、确认程度和限制。 |
| 审稿与标题 | 初稿、证据、[标题模块](../../ai-title-generator/SKILL.md)、[审稿模块](../../wewrite-review/SKILL.md) 和本机审稿规范。 | 一份认定的 `article.md`、`titles.md`、审稿报告。正文用单一 H1 作题名。摘要独立。复核标题、首屏、日期、数字和关键引语的归属。按模块的参数运行 `wewrite content-eval` 辅助检查。 |
| 配图和排版 | 正文、图位、官方素材、版权及可用方式。按 [图怎么选](editorial.md#图怎么选) 和本机配图规范处理。 | 真实图片文件或相应视频、图注、来源、封面及用图清单。为每图写明接在哪句话后、承担什么信息。移动端检查封面裁切及正文图文字。封面和正文图文件用相对路径记录。 |
| 发布前终审 | 最新稿和审稿报告、全部资产及账号字段。 | 同版本核查结果。核对标题、摘要、署名、首尾、段间留白、图序、来源、阅读原文链接及封面。正文和独立字段分开。剪贴板的富文本只含正文和图，一级标题作为编辑器标题栏使用。 |

三张选题卡各写主题、实际进展、对读者的影响、稿件角度、可用配图和一手链接。正文写作前把关键主张逐项对应到来源。术语、口径、引语或图表有改动时，把对应材料一起更新。在文末留能支撑主线的少量出处，完整资料进入 `evidence.md`。

终审时把图注和下一句正文连起来读一遍。读者看到的是图片内容、出处或必要口径。截图和排版步骤留在素材记录。

遇到时效、财经或监管题时，把宣布时间、事件生效日和市场交易日分列，量化跨度按同一口径复算。第三方公开发言回看原帖或可溯源转载，正文写清身份和发言所指。只找到存档或媒体嵌帖时，在核查表注明。行情图依据已核对的实际记录绘制，过程图按日期区别决定、公告和待发生事项。

## 交接到微信或秀米

### 微信公众号审稿页

默认准备本地可复制的审稿页和图片包，无需登录。先安装 [WeWrite 依赖](../../../../WEWRITE.md)，再从仓库根目录执行。摘要、封面和输出目录必填，封面参数相对于稿件所在目录。署名按用户已确认的名称填。原文链接选与本篇主线直接相关、可访问的公开一手出处。署名或原文链接无法确认时，对应参数可省略。

```powershell
python -X utf8 wechat_handoff.py examples/nvidia-2026-11-24/article.md --summary "离任11天，黄仁勋全票复职。董事会五天内改口，英伟达收涨31.48%。" --author "信号之外" --cover images/cover.jpg --source-url "https://nvidianews.nvidia.com/news/nvidia-board-reinstates-jensen-huang-as-president-ceo-and-board-director" --out exports/nvidia-review
```

在输出目录确认 `review.html` 和 `handoff.json`。查清单中的标题、摘要、署名、原文链接、封面、按正文顺序记录的图像路径及正文和预览的 SHA-256。对比图片顺序、正文首尾和最新正文，检查引用链接与公开原文分栏。打开审稿页看手机宽度。点击复制后，用本地页验证实际剪贴板含 `text/html`，且图片数量和小标题与审稿版一致。只看到复制提示、纯文本或旧剪贴板内容时，继续验证富文本来源和接收端。

站点访问或账号权限受限时按人工交接。运营者先把富文本粘贴到正文，分别填写标题、摘要、作者和原文链接，再从审稿页下载封面上传。正文第一张和清单中的封面相同时，也可在编辑器中从正文选第一张。粘贴后预览确认图片真实加载、裁切和段距。

### 微信公众号官方草稿

用户要求草稿交接且账号管理员已授权并配置时，按 [WeWrite 草稿说明](../../../../WEWRITE.md#交给运营者在公众号编辑页终审) 执行。网页登录与接口配置分别完成。AppID、AppSecret、IP 白名单或素材和草稿权限未就绪时，继续交付本地富文本。只使用官方接口，凭据从本机账户配置读取。WeWrite 4.2.0 的 `publish` 子命令实际创建草稿，核对调用范围后再执行。取得真实稿件 ID 后用官方读取端确认标题、摘要与正文图片。该命令没有原文链接参数，编辑页另外设置并核对「阅读原文」。有请求超时或平台返回不确定时先核对草稿，确认结果后再决定是否重试。

### 秀米

用户选择秀米时按 [秀米交接说明](../../../../XIUMI.md) 批量导入。读取当前账号可用入口。Word 导入会重新排版，图文先一次导入，再单独设置标题、摘要和封面。保存后重新打开同一图文，通过预览检查图片、段间留白、首尾和来源。公众号同步需要独立授权，保存到秀米即记为秀米稿。

## 怎么记录已完成

下表各步骤按实际证据写入 `run.md`。保留已使用工具、正文版本和下一步，具体账号回执只留在获准保存的位置。

| 可以报告的状态 | 证据 |
| --- | --- |
| 已审稿 | 当前正文和对应版本的审稿报告，事实、图表和措辞已核对。 |
| 本地包已验收 | `review.html`、`handoff.json` 与本轮检查，说明预览以及富文本验证的实际结果。 |
| 秀米已保存 | 保存成功，重开指定图文并核对关键内容。 |
| 公众号草稿已创建 | 获得真实公众号草稿回执，回读同一草稿校验。未配置接口、模拟运行和截图中的预览各自记录原状态。 |
| 运营者已预览或发布 | 分别记录由运营者明确确认的状态和日期，或可核实的正式发布结果。预览页只证明预览。 |

当前步骤交接时，最小文件集为 `run.md`、`article.md`、`evidence.md`、`titles.md`、审稿报告、封面和正文素材、对应交付物。归档使用相对路径，将正文和资产一起保存。账号秘密、登录态、可识别的临时预览链接不进稿包或 Git。按 [复盘与恢复](../../../../EDITORIAL-HISTORY.md) 保存可复用的规则和已授权归档的样稿。
